# 硬轮廓损失重构 — 设计文档

日期：2026-08-09

## 目标

把现有四项损失改成三项。振幅不变；轮廓的定义从"逐轮可导的软包络"换成"占比锁死的硬 mask"；直方图从整图收窄到轮廓内；轮廓占比损失删除。

改动后的损失构成：

| | 现在 | 改后 |
|---|---|---|
| 1 | 振幅 | 振幅（不变） |
| 2 | 整图直方图 | **轮廓内**直方图 |
| 3 | 背景（软轮廓外趋 0） | 背景（硬 mask 外趋 0，算法不变） |
| 4 | 轮廓占比 | **删除** |

## 可导性

新轮廓是"模糊 → 取前 k 个最亮像素置 1"，等价于在模糊图的 (1−ρ) 分位点上做硬阈值。mask 本身几乎处处梯度为 0，不可导。但它不需要可导，因为两个消费者都只把它当**选择器**用：

- 背景损失 `mean((1-mask)*pred)²` —— 现有代码里 `contour.detach()` 本来就把轮廓当常量了。换成硬 mask 行为一致，梯度照样经 `prediction` 流回网络。
- 轮廓内直方图 —— `prediction[mask]` 对被选中的像素值仍然可导，只是不对"哪些像素被选中"可导。

真正需要可导轮廓的只有占比损失（它算 `d(contour.mean())/d(pred)`，必须软 sigmoid 才有梯度）。而这一项恰好因为 top-k 构造把占比钉死成恒等相等、损失恒为 0 而失去意义。所以"硬 mask + 删占比损失"是配套的，不存在半吊子状态。

## 轮廓算法

轮廓不再是一个函数，而是两个——源图侧与输出侧算法不同，靠一个整数把它们锁在一起。

### 源图侧（跑一次）

现有 `dynamic_contour` 去掉 sigmoid。判据、减基线、峰值归一化全部保留。

```python
def source_contour(source, sigma, threshold):
    blurred = gaussian_blur(source, sigma)
    contrast = blurred - blurred.amin()
    return (contrast / contrast.amax().clamp_min(1e-6) > threshold).float()
```

输入的 `source` 就是 `load_source` 的返回值——灰度、反转、扩画布、pad 到 16 倍数都已完成，顺序符合要求（先做固有预处理，再高斯模糊）。

### 输出侧（每轮）

模糊后取前 k 个最亮像素。

```python
def topk_contour(prediction, sigma, k):
    blurred = gaussian_blur(prediction, sigma).flatten()
    mask = torch.zeros_like(blurred)
    mask[torch.topk(blurred, k).indices] = 1.0
    return mask.view(1, 1, *prediction.shape[-2:])
```

### 为什么锁 k 而不是锁 ρ

直接取 `k = int(source_mask.sum())`，而不是先算 ρ 再乘回 N。后者有两次浮点取整，两边像素数会差几个。走整数则两个 mask 的像素数**严格相等**，轮廓内直方图不需要任何长度补偿。ρ 只用于显示（`k / N`）。

`k == 0` 时（阈值给得过高，源图 mask 全空）直方图两侧都是空张量，CDF 的 `mean(dim=1)` 会出 NaN。`train.py` 在标定前对此显式报错退出，而不是静默产出 NaN——这是参数给错，不是需要容错的运行时状态。

用 `topk(...).indices` 散射而不是 `>= 阈值` 比较，也是为了这个严格性：并列值在阈值比较下会让 mask 多出几个像素。

`zeros_like` 出来的 mask 天然 `requires_grad=False`，是纯常量。`background_loss` 里那句 `contour.detach()` 因此变成冗余，删除，行为等价。

### 二值化方法的选型

沿用现有判据（减基线 + 峰值归一化 + 相对阈值），只去掉 sigmoid。考虑过的替代都更差：

- **大津法 / 三角法** —— 自动定阈值，`--contour-threshold` 这个旋钮就没了。而且大津法假设前景背景像素量级可比，这里 expand=2 时背景占 75%，类别极度不平衡会把阈值压得过低，圈出偏大的包络。
- **绝对阈值 / 均值倍数** —— 随图片整体亮度漂移，比峰值归一化更差。

沿用现有公式还有个实际好处：算出的 ρ 与之前所有实验的软轮廓均值口径一致，历史结果能直接对比。

### 已知风险与退路

硬 mask 的边界像素会逐轮跳变：一个像素这轮在 mask 内被要求符合物体亮度分布，下轮掉出去被背景损失要求趋 0，可能引起损失振荡。缓解在于 mask 从**模糊图**算出、模糊图逐轮变化平缓，真正会跳的只有边界一圈，内部稳定。

先按硬 mask 实现。**若实测出现振荡**，退路是把第 k 大值当作 sigmoid 中心恢复平滑（占比仍近似严格）。这条退路本次不实现。

附带收益：散布亮点这种投机解走不通。若输出把亮度散成满画布，模糊图接近平坦，top-k 只圈住其中 ρ 比例，剩下 1−ρ 的位置仍有亮度，背景损失直接重罚。

## 三项损失

### 振幅

一行不动。

### 背景

算法完全不变，只是 `contour` 换成新的硬 mask，删掉已成冗余的 `.detach()`：

```python
def background_loss(prediction, contour):
    return torch.mean(((1.0 - contour) * prediction).square())
```

### 轮廓内直方图

现有 `soft_histogram_cdf_loss` 从整图版改成收 mask 版。**目标分布** = 源图像素在源图 mask 内的取值；**预测分布** = 输出像素在输出自己的 mask 内的取值。两个 mask 空间位置不同，像素个数严格相等。

不在源图 mask 内取预测值——那等于把源图轮廓的位置当成监督，违反项目"不使用原图轮廓的位置或形状作为监督"的前提。

```python
def masked_histogram_cdf_loss(prediction, target, prediction_mask, target_mask, bins, softness):
    centers = torch.linspace(0, 1, bins, device=prediction.device, dtype=prediction.dtype)
    prediction_values = prediction[prediction_mask > 0.5]
    target_values = target[target_mask > 0.5]
    prediction_cdf = torch.sigmoid((centers[:, None] - prediction_values[None, :]) / softness).mean(dim=1)
    target_cdf = torch.sigmoid((centers[:, None] - target_values[None, :]) / softness).mean(dim=1)
    return F.mse_loss(prediction_cdf, target_cdf)
```

CDF 那两行数学上与现在完全一致，改的只是喂进去的两个集合。目标侧的 `target_values` 每轮都是同一个东西，在训练前算一次缓存——省掉每轮一次 `bins × k` 的 sigmoid，纯粹省时间，不改数值。

收窄到轮廓内还提高了信息密度：原来整图 CDF 里有大量背景 0 像素两边天然吻合，这部分"平凡正确"稀释了真正的分布约束。

### 占比损失

删除 `contour_area_ratio_loss`。k 严格相等使它恒为 0，留着只是白算。

## 权重

`CalibratedWeights` 从三项标定降到两项，标定公式不动：

```
β_i = SHARE_i × L_amp,0 / L_i,0
```

SHARE 从 `config.py` 的常量变成构造参数，由 CLI 传入。`SHARE_AREA_RATIO` 删除。

默认值：**直方图 0.5、背景 0.10**。

理由：压黑风险原本靠占比项对冲，现在轮廓内直方图对冲得更强——输出全黑时 mask 内是个集中在 0 的分布，源图 mask 内全是中高亮度，CDF 差距被最大化，罚得比占比那个标量约束狠得多。所以直方图接过占比原来的主力位置（0.5），背景维持 0.10。总权重和从 0.9 降到 0.6，相对抬高了振幅这个唯一硬数据的地位。

施压分工也变干净了：mask 内由直方图 + 振幅负责，mask 外由背景 + 振幅负责，边界清晰，没有原来"两项都在全画布重叠施压"的拉扯。

### 宽度由布局算出

不逐个写死 px。`box-sizing: border-box` 已全局生效，做法是让 `.field` 均分行宽、输入框撑满自己的 field：

```css
.field { flex: 1; min-width: 0; }
.fields-row { display: flex; gap: 14px; }   /* 去掉 flex-wrap: wrap */
select, input[type="text"] { width: 100%; }
```

同时删掉 `app.js` 里全部七处 `style.width = "..."`。

`min-width: 0` 必须有，否则 select 的内容宽度会顶破 flex 收缩。去掉 `flex-wrap` 是因为每行只放一到两个，不该再换行。

## 离线指标

`support_iou` 保留，含义不变，但两侧都变成硬 mask，IoU 里的 `> 0.5` 阈值从"切软包络"变成"恒等取整"。因为两个 mask 面积严格相等，IoU 与 Dice 现在是单调等价的，读数含义更干净：交集除以 `2k − 交集`。

`train.py` 里评估用的 `evaluation_contour` 要跟着换成 `topk_contour(evaluation_prediction, sigma, k)`，用同一个 k。IoU 是前端图表的两条曲线之一，这里换漏了会静默错。

`plot_support` 不用改，两侧仍是 0/1 图。子图标题里"软粗轮廓"之类的措辞要改成硬轮廓。

## 验证

1. 源图 mask 与输出 mask 的像素数严格相等 → 断言 `source_mask.sum() == topk_mask.sum()`。
2. 反向传播能跑通、梯度非零 → 单步 `total.backward()` 后检查 `model` 参数 grad 范数 > 0。
3. mask 是常量 → 断言 `topk_contour(...).requires_grad is False`。
4. 端到端短跑（如 50 轮）不报错，`history.csv` 列数正确、`convergence.png` 出 10 个面板。
5. 预览接口返回的 ratio 与训练脚本打印的 "Source contour ratio" 一致（同参数下）。
