# 前端实时损失曲线改为三项归一化损失

## 问题

前端左侧那块实时画布标着「总损失」，画的是 `weights.contributions(...).sum()`，即

    weighted = Σ_i w_i · exp(-s_i) · L̂_i

这个量读不出训练好坏。Kendall 加权的不动点是 `exp(-s_i) = 1/L̂_i`，代入后每项贡献收敛到 `w_i` 本身，于是 `weighted` 被钉在 `Σ w_i = 1 + 0.5 + 0.10 = 1.6` 附近。它测的是 s 与损失的错配程度，不是损失水平。

两次真实运行的证据：

- `results/run_123_x1.5_20260811_022018`：weighted 走 1.60 → 0.89 → 之后一路在 1.00 上下摆到第 30000 轮，同期归一化振幅损失 `L̂_amp` 从 1.0 降到 0.156（降了 6 倍多）。曲线平，损失在降。
- `results/run_567_x1_20260811_015010`：weighted 后半段从 0.19 **升**到 0.68，看着像发散。实际是 `s_amp` 还在从上方追不动点（-1.9 → -3.0），`exp(-s)` 涨 2.9 倍而 `L̂_amp` 只降 0.73 倍。曲线升 ≠ 变差。

## 为什么不是加回 `+s_i`

初始判断是「去掉 `+s_i` 导致误判」，加回去更糟。`s_i` 长期近线性下降，`total = weighted + Σ w_i·s_i` 就跟着近线性走向 -∞：run_123 从 +3.0 单调滑到 -6.7，全程无拐点，而同期 SSIM 在第 12500 轮见顶 0.575 后跌回 0.358。一条完美下降的曲线配一个正在恶化的重建，比现在这条更能骗人。

`+s_i` 是阻止权重趋零的正则项，属于优化目标的构造，本身不携带「拟合得多好」的信息。它该留在 `total` 里被最小化，不该进给人看的曲线。

## 方案

前端左图从单条「总损失」改为三条归一化损失 `L̂_i = L_i / L_i,0`（对数轴）：振幅、直方图、背景。右图 IoU 不变。

三条线起点都是 1.0（`L̂_i,0 = 1` 由定义保证），往下是在降。可以直接读出哪项还在动、哪项停了、有没有哪项被饿死——这是钉在 1.6 附近的 weighted 完全给不出的。

选归一化值而非原始值，是因为三项原始量级差近四千倍（振幅 ~1e-5、直方图 ~1e0、背景 ~1e0），同轴画不了。除以 L_i,0 后三条线共享起点，形状与原始值在对数轴上只差垂直平移。

### 后端（`backend/train.py`）

`emit_metric` 现在发 `total=weighted`，改发三项归一化损失。`weights.initial` 里已存着 L_i,0，一行即可：

```python
normalized = (torch.stack([amplitude, histogram, background]) / weights.initial).tolist()
emit_metric(args.stream_metrics, iteration=iteration, losses=normalized,
            iou=iou, ssim=ssim_value)
```

- `weighted` 局部变量除了喂前端曲线无其他用处，一并删除。
- `total` 保留在 history / CSV / 终端日志里，不动。
- `ssim` 字段本来就在传（前端目前丢弃），保留原样。

### 前端（`frontend/app.js`）

`MiniChart` 从单序列线性轴扩为多序列 + 可选对数轴，IoU 图继续用单序列线性轴，共用同一个类：

- 构造签名 `(canvas, label, color)` → `(canvas, series, options)`，`series` 为 `[{label, color}]`，`options.logScale` 可选。
- `push(x, ys)` 收数组；`ys` 长度与 `series` 一致。
- 标题行改为图例：色点 + 名称（振幅 / 直方图 / 背景）。
- `logScale: true` 时 y 轴走 log10，刻度标 `1e-2` 这类。非正值的点跳过不画（背景项理论上可到 0）。

配色沿用 Apple 系统色，与现有的蓝 `#0066cc` / 绿 `#34c759` 一套：

| 序列 | 颜色 |
|---|---|
| 振幅 | `#0066cc` |
| 直方图 | `#ff9500` |
| 背景 | `#af52de` |

`handleMsg` 的 `metric` 分支改为 `exp.lossChart.push(msg.iteration, msg.losses)`。

## 不做

- **离线 `convergence.png` 不动。** 它的三个损失面板画原始值，在对数轴上与归一化值形状一致。其中 `total` 面板有和前端同样的误导性（单调滑向 -∞），但本次只改前端。
- **不加"重建质量"曲线。** 本改动让曲线能回答「优化是否健康」，回答不了「重建是否在变好」——run_123 的 `L̂_amp` 从 1.0 单调降到 0.156 全程无拐点，同期 SSIM 已腰斩。IoU 图能捕捉一部分（那次 IoU 也在第 10000 轮见顶 0.657），但不完整。这是已知局限，不在本次范围。

## 验收

1. 启动前端跑一次短训练（几百轮足够），左图出现三条线、带图例、对数轴，起点均为 1.0。
2. 右图 IoU 曲线与改动前一致（单条绿线、线性轴）。
3. 后端 `__METRIC__` 行含 `losses` 三元数组，不再含 `total`。
